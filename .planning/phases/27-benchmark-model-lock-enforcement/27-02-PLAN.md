1. The current BenchmarkRunner.run() only does retrieval queries (search engine). The model identity check applies to a **prompt execution** context, not retrieval. Looking at the architecture:
   - The benchmark runner currently tests RETRIEVAL quality (search engine hit@k, MRR)
   - Model lock enforcement needs to be applied when the benchmark runs LLM prompts (the RAG benchmark A/B test where an LLM answers questions)

The runner's `searchEngine.search()` returns `RetrievalResult[]`. We need to extend the interface to also support an optional LLM execution path. Add:

```typescript
export interface LlmExecutor {
  execute(prompt: string, systemPrompt?: string): Promise<{ response: string }>;
}
```

However, looking at the existing architecture more carefully — the BenchmarkRunner tests retrieval, not LLM responses. The LLM-IDENTITY enforcement should be added to the **prompt execution** layer that the RAG benchmark uses when it sends prompts to the LLM.

**Simpler approach per D-07:** The identity block request is injected into the system prompt. The raw response comes back from whatever executes the benchmark prompts. Add a `rawResponse?: string` field to `QueryResult` and a post-processing step.

Add to BenchmarkRunner constructor: optional `configuredModel?: string` from BenchmarkConfig.

After computing each QueryResult, if `rawResponse` is available:

```typescript
import { parseIdentityBlock, compareModelIdentity } from './identity-parser.js';

// After queryResults.push(...)
if (rawResponse) {
  const identity = parseIdentityBlock(rawResponse);
  if (!identity) {
    qr.identityMissing = true;
  } else {
    qr.identityMissing = false;
    if (this.config.configuredModel) {
      qr.modelMismatch = !compareModelIdentity(identity.model!, this.config.configuredModel);
      if (qr.modelMismatch && this.config.strictModel) {
        throw new Error(
          `Model mismatch detected: expected "${this.config.configuredModel}", got "${identity.model}". Aborting (--strict-model).`,
        );
      }
    }
  }
}
```

2. After the query loop, compute runIntegrity:

   ```typescript
   const hasAnyIdentity = queryResults.some((qr) => qr.identityMissing === false);
   const hasAnyMismatch = queryResults.some((qr) => qr.modelMismatch === true);
   let runIntegrity: 'full' | 'partial' | 'unknown';
   if (!hasAnyIdentity) {
     runIntegrity = 'unknown';
   } else if (hasAnyMismatch) {
     runIntegrity = 'partial';
   } else {
     runIntegrity = 'full';
   }
   ```

   Add `runIntegrity` to the returned BenchmarkRun object.

3. For the current retrieval-only path: `rawResponse` won't be present, so identity fields stay undefined and runIntegrity='unknown'. This is backward-compatible.

4. Export `LlmExecutor` interface from index.ts for downstream use.

5. Write tests using mock rawResponse strings in QueryResult.
