1. `extractSuperclass(node: Parser.SyntaxNode): string | undefined` — For `class_declaration` nodes, find the `superclass` field child (tree-sitter field name). 2. `extractInterfaces(node: Parser.SyntaxNode): string[] | undefined` — For `class_declaration`, find the `interfaces` field child (a `type_list` node). For `interface_declaration`, find `extends_type_list` or `extends_interfaces` field. Map each `type_identifier` child to its text. Return array or undefined if empty.

For tree-sitter Java grammar specifics:

- `class_declaration` has field `superclass` → child type is `type_identifier` or `generic_type`
- `class_declaration` has field `interfaces` → child type is `super_interfaces` containing `type_list`
- `interface_declaration` has field `extends_interfaces` → `extends_interfaces` containing `type_list`
- `type_list` contains comma-separated `type_identifier` nodes

Note: tree-sitter field names may vary. Use `node.childForFieldName('superclass')` first; if null, iterate children looking for nodes after `extends` keyword. Debug with `node.children.map(c => c.type)` if needed.

In `packages/ast-parser/src/parsers/typescript.ts`, add hierarchy extraction:

tree-sitter TypeScript grammar structure for classes:

- `class_declaration` or `abstract_class_declaration` has a `class_heritage` child
- `class_heritage` contains `extends_clause` and/or `implements_clause` children
- Each clause has children that are type references (type_identifier or generic_type)

Add function `extractHeritage(node: Parser.SyntaxNode): { superclass?: string; interfaces?: string[] }`:

1. Find `class_heritage` child of the class declaration node (iterate children, look for type `class_heritage`)
2. Within class_heritage, find `extends_clause` → first type reference = superclass name
3. Within class_heritage, find `implements_clause` → all type references = interfaces
4. For `interface_declaration`: look for `extends_type_clause` or similar — interfaces extending others go into the `interfaces` field

For type references that are `generic_type`, take only the first `type_identifier` child (strip generic params).

In the main parsing logic where class/interface chunks are created, call `extractHeritage` and set the fields on the chunk.

Note: tree-sitter TS grammar node names may differ slightly. The `class_heritage` node may not exist if no extends/implements. Check `node.children` types to confirm. Alternative: look for child nodes of type `extends_clause` directly on the class_declaration.
</action>
