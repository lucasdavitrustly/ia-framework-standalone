  <action>
    1. Create a `parseRepoPath` utility function (either in get-file.ts or a shared util):
       ```typescript
       export function parseRepoPath(input: string): { repo?: string; path: string } {
         // Only match lowercase alphanumeric + hyphens before colon, avoid Windows drive letters (single char)
         const match = input.match(/^([a-z][a-z0-9-]*):(.+)$/);
         if (match) return { repo: match[1], path: match[2] };
         return { path: input };
       }
       ```

    2. Update `getFileHandler` in get-file.ts:
       - Parse input.path with parseRepoPath
       - If repo is specified, pass filter `{must: [{key: 'repoId', match: {value: repo}}]}` to engine (need to extend Engine type to accept filter in getFile, OR filter results post-retrieval by checking `result.repoId === repo`)
       - If no repo prefix, get all results and group by repoId
       - Format output with repo headers per group:
         ```
         ## [repo-name]
         ### chunkType: Name (lines X-Y)
         ```
       - In structuredContent, include `repo` field per chunk
       - Per D-06: if same path exists in multiple repos, return ALL matches with attribution

    3. Write tests in `packages/mcp-server/src/tools/get-file.test.ts`:
       - Test parseRepoPath parsing (with prefix, without, Windows path)
       - Test multi-repo grouping in output
       - Test single-repo filter when prefix provided

    Per D-06: auto-resolve across all repos, return all matches. Per D-07: support `repo:path` prefix syntax.
