    Per D-09: After indexing completes (after the pipeline loop), check if any chunks lack repoId:

    ```typescript
    // Backward-compat check: warn about chunks without repoId (D-09)
    try {
      const totalPoints = await vectorStore.countPoints();
      const pointsWithRepo = await vectorStore.countPoints({
        must: [{ key: 'repoId', match: { any: registry.getRepos().map(r => r.name!) } }]
      });
      const orphanCount = totalPoints - pointsWithRepo;
      if (orphanCount > 0) {
        console.log(`\n  ⚠ ${orphanCount} chunks lack repoId (indexed before multi-repo support).`);
        console.log(`    Run "ia-framework index --force" to re-index all repos and add repoId to all chunks.`);
      }
    } catch {
      // Non-fatal — skip warning if count fails
    }
    ```

    Note: The `match: { any: [...] }` filter checks for presence of repoId with any known value. Chunks without the field will be excluded from the count.

    Actually, Qdrant filter for "field exists" is simpler:
    ```typescript
    const pointsWithRepo = await vectorStore.countPoints({
      must: [{ key: 'repoId', match: { except: [] } }]
    });
    ```

    Or use a HasId filter. Check Qdrant docs — simplest approach: use `has_id` or filter where `repoId` is not null. The most reliable Qdrant approach:
    ```typescript
    // Count points that DO have repoId field (non-null)
    const pointsWithRepo = await vectorStore.countPoints({
      must: [{ is_null: { key: 'repoId' }, _not: true }]
    });
    ```

    Alternatively, use the Qdrant "IsNull" condition inverted. Check the actual Qdrant filter syntax the project uses in `packages/vector-store/src/qdrant.ts` and use the correct format. The key point is: count chunks missing `repoId`, warn if > 0.
