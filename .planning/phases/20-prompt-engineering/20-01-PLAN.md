    - buildPrompt without examples still works (backward compat) but no example sections
    - Prompt text contains "A class and all its methods MUST be a single chunk"
    - Prompt text contains "If a class exceeds 100 lines, split into logical method groups but always prefix each sub-chunk summary with the class name"
    - Prompt text contains "minimum 5 lines per chunk"
    - Prompt text contains instructions about domain terminology: "Describe what the code DOES using domain terminology (handles, validates, orchestrates, manages)" and "Do NOT describe syntax (this function takes X and returns Y)"
    - PROMPT_CONTENT_HASH changes after these modifications
  </behavior>
  <action>
    1. Modify `buildPrompt()` signature to accept optional third parameter:
       ```typescript
       export function buildPrompt(
         sourceCode: string,
         fileName: string,
         options?: { examples?: { good: string; bad: string } }
       ): string
       ```

    2. Add to the Rules section of the prompt (after existing rules):
       ```
       - A class and all its methods MUST be a single chunk. Never split a class across chunks.
       - If a class exceeds 100 lines, split into logical method groups but always prefix each sub-chunk summary with the class name.
       - Minimum chunk size: 5 lines. Do not create chunks smaller than 5 lines — merge them with adjacent context.
       - Summaries MUST describe what the code DOES using domain terminology (handles, validates, orchestrates, manages, transforms, routes, etc.)
       - Do NOT describe syntax structure ("this function takes X and returns Y"). Describe PURPOSE and BEHAVIOR.
       ```

    3. If `options?.examples` provided, insert before the source code section:
       ```
       ## Examples

       GOOD boundary detection:
       ${examples.good}

       BAD boundary detection (avoid this):
       ${examples.bad}
       ```

    4. Update `buildPromptTemplate()` to pass empty options so hash stays deterministic.

    5. Update callers: In `llm-chunker.ts`, `buildPrompt` calls should pass examples when available. Add an optional `examples` parameter to `chunkFile()` and `chunkFileWithWindowing()` params, thread through to `buildPrompt()`.

    6. Update `LlmChunkingStrategy` constructor to accept optional `examplesDir` and load examples in `chunk()` (cache after first load). Pass examples to `chunkFile()`.

    7. Write tests in `prompt.test.ts`:
       - Prompt without examples contains class grouping rules
       - Prompt with examples contains "GOOD boundary" and "BAD boundary" sections
       - Prompt contains "domain terminology" guidance
       - Prompt contains "minimum 5 lines" rule
