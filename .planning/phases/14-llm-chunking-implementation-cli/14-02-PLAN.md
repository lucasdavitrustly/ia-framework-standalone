    2. **llm-strategy.ts** — LlmChunkingStrategy (per D-05):
       ```typescript
       export interface LlmChunkingOptions {
         model: string;         // e.g. 'llama3.2:latest'
         ollamaUrl?: string;    // default: 'http://localhost:11434'
         cachePath: string;     // path to llm-chunk-cache.json
         onFileProgress?: (fileName: string, fileIndex: number, totalFiles: number) => void;
       }

       export class LlmChunkingStrategy implements ChunkingStrategy {
         readonly name = 'llm';
         constructor(options: LlmChunkingOptions);
         async chunk(filePath: string, config: ChunkingConfig): Promise<CodeChunk[]>;
         async loadCache(): Promise<void>;
         async saveCache(): Promise<void>;
       }
       ```
       - `chunk()` flow:
         a. Read file content via `readFile()`
         b. Compute SHA-256 of content
         c. Check cache: if hit, reconstruct CodeChunks from cached boundaries + current file content
         d. If miss: call `chunkFile()` from llm-chunker (which handles windowing)
         e. Map LLMChunk[] → CodeChunk[]:
            - `chunkType: 'semantic'` (per D-02)
            - `description: llmChunk.summary` (per D-03, D-04)
            - `imports: []`, `exports: []` (per D-01 — no AST analysis for LLM chunks)
            - `name`: derive from summary — first 5 words, slugified (e.g., "handles-user-authentication-and-session")
            - `id`: createHash('sha256').update(`${filePath}:${startLine}:${endLine}`).digest('hex').slice(0, 32) formatted as UUID
            - `content`: extract lines from file content (startLine to endLine, 1-indexed)
         f. Cache result, save cache
       - Retry-once on Ollama failure per file (per D-19): try once, if fails retry once, if still fails throw (pipeline already skips on error)
       - `onFileProgress` callback for CLI per-file progress (per D-18)
