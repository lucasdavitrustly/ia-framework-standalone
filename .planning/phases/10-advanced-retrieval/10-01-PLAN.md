## Goal

Fix the remaining gaps in the `DependencyGraph` implementation: export from barrel, wire `upsertEdges()` into the indexing pipeline, and verify everything builds and tests.

## Context

The `DependencyGraph` class was implemented in a prior session with a full test suite (8 tests). Two gaps remain:

1. **Not exported** from `packages/retrieval/src/index.ts` barrel
2. **`upsertEdges()` never called** in `IndexingPipeline.run()` — the interface is declared, tests expect the call, but the actual pipeline code is missing the invocation after chunk parsing

## Tasks

### Task 1: Export DependencyGraph from retrieval barrel

**File:** `packages/retrieval/src/index.ts`

Add exports for `DependencyGraph` and `DependencyGraphConfig`.

### Task 2: Wire upsertEdges into IndexingPipeline

**File:** `packages/indexer/src/pipeline.ts`

After chunks are parsed for each file (and before embedding), call:
```ts
if (config.dependencyGraph) {
  const fileImports = chunks.flatMap(c => c.imports);
  if (fileImports.length > 0) {
    config.dependencyGraph.upsertEdges(filePath, fileImports, config.targetProjectPath);
  }
}
```

The test suite already expects this behavior — this should make existing tests pass.

## Decisions / Notes

- DependencyGraph lives in packages/retrieval (retrieval concern, consumed by SearchEngine in 10-02)
- IndexingPipeline receives DependencyGraph as optional injectable — maintains testability
- SQLite file is .ia-framework/graph.sqlite (separate from metrics.sqlite)
- File-level edges only (not chunk-level) — simpler, sufficient for 1-2 hop expansion
