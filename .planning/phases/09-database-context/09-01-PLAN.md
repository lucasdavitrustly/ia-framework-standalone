# Phase 9 Plan 1: db-context package + pipeline extension

## Objective

Create the `@ia-framework/db-context` package implementing the `ContextSource` interface for PostgreSQL database schema indexing, and extend the `IndexingPipeline` to accept and process `ContextSource[]` alongside file-based chunks.

## Context

@turbo.json

## Architecture Decision (already agreed — do not revisit)

`ContextSource` is a minimal interface in `@ia-framework/core`:
```ts
interface ContextSource {
  name: string
  getChunks(): Promise<ChunkMetadata[]>
}
```

`PostgresSource` is the first implementation. No registry, no plugin system. The indexing pipeline calls `getChunks()` after file processing and embeds/upserts identically. `pg.Pool` is constructor-injected for full mockability without `vi.mock()` magic.

### Task 1 — Extend `@ia-framework/core` types
`type="auto"`

**Changes to `packages/core/src/types/index.ts`:**
- Extend `ChunkMetadata.chunkType` union to include `'table' | 'view'`
  - Before: `'function' | 'class' | 'interface' | 'type' | 'enum' | 'module' | 'other'`
  - After: `'function' | 'class' | 'interface' | 'type' | 'enum' | 'module' | 'other' | 'table' | 'view'`
- Add `ContextSource` interface after `ChunkMetadata`:
  ```ts
  /**
   * A pluggable context source that produces indexable chunks.
   * Implement this interface to add new context types (DB schema, docs, etc.)
   * to the indexing pipeline alongside code chunks.
   */
  export interface ContextSource {
    /** Human-readable name for logging (e.g. 'postgres', 'docs') */
    name: string;
    /** Produce all chunks from this source for embedding and storage */
    getChunks(): Promise<ChunkMetadata[]>;
  }
  ```
- Export `ContextSource` from `packages/core/src/index.ts`

**Note:** `ChunkPayload.chunkType` in `@ia-framework/vector-store` is already typed as `string` (not the union), so no breaking change there.

**Done criteria:**

**`packages/db-context/src/postgres-source.ts`** — PostgresSource implementing ContextSource:

Key implementation details:
- Constructor signature: `constructor(config: DatabaseConfig, pool?: Pool)` — if `pool` is not provided, creates `new Pool({ host, port, database, user, password, ssl: ssl ? { rejectUnauthorized: false } : false })`
- `testConnection(): Promise<{ connected: boolean; tableCount: number }>` — runs `SELECT COUNT(*) FROM information_schema.tables WHERE table_schema = 'public'`; returns `{ connected: false, tableCount: 0 }` on any error (never throws)
- `getChunks(): Promise<ChunkMetadata[]>` — queries information_schema for tables + views, then columns, then foreign keys; builds one chunk per table/view
- `executeQuery(sql: string): Promise<QueryResult>` — runs arbitrary SQL, returns `{ rows, rowCount }`
- `close(): Promise<void>` — calls `this.pool.end()`

**`getChunks()` information_schema queries:**

```sql
-- Tables and views
SELECT table_name, table_type
FROM information_schema.tables
WHERE table_schema = 'public'
ORDER BY table_name;

-- Columns for each table
SELECT column_name, data_type, is_nullable, column_default, character_maximum_length
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = $1
ORDER BY ordinal_position;

-- Foreign keys (single query for all tables)
SELECT
  tc.table_name,
  kcu.column_name,
  ccu.table_name AS foreign_table_name,
  ccu.column_name AS foreign_column_name
FROM information_schema.table_constraints AS tc
JOIN information_schema.key_column_usage AS kcu
  ON tc.constraint_name = kcu.constraint_name AND tc.table_schema = kcu.table_schema
JOIN information_schema.constraint_column_usage AS ccu
  ON ccu.constraint_name = tc.constraint_name AND ccu.table_schema = tc.table_schema
WHERE tc.constraint_type = 'FOREIGN KEY' AND tc.table_schema = 'public';
```

**Chunk ID generation:**

import { createHash } from 'node:crypto';
function tableChunkId(tableName: string): string {
  return createHash('sha256').update(`db:${tableName}`).digest('hex').slice(0, 32);
}

Add context source processing after the file embedding loop (before the storing stage):
```ts
// Process additional context sources
if (config.contextSources && config.contextSources.length > 0) {
  for (const source of config.contextSources) {
    logger.info({ source: source.name }, 'Processing context source');
    try {
      const sourceChunks = await source.getChunks();
      logger.info({ source: source.name, count: sourceChunks.length }, 'Got chunks from context source');

      // Embed source chunks in batches using same pipeline
      for (let i = 0; i < sourceChunks.length; i += embeddingBatchSize) {
        const batch = sourceChunks.slice(i, i + embeddingBatchSize);
        const texts = batch.map((c) => c.content);
        const vectors = await embeddingProvider.embedBatch(texts);

        for (let j = 0; j < batch.length; j++) {
          const chunk = batch[j]!;
          const vector = vectors[j]!;
          const payload: ChunkPayload = {
            chunkId: chunk.id,
            filePath: chunk.filePath,
            relativePath: chunk.relativePath,
            language: chunk.language,
            chunkType: chunk.chunkType,
            name: chunk.name,
            content: chunk.content,
            startLine: chunk.startLine,
            endLine: chunk.endLine,
            imports: chunk.imports,
            exports: chunk.exports,
            indexedAt: chunk.indexedAt,
          };
          vectorPoints.push({
            id: chunk.id,
            textVector: vector,
            codeVector: vector,
            payload,
          });
        }
        progress.chunksIndexed += batch.length;
        onProgress?.({ ...progress });
      }
    } catch (err) {
      logger.error({ source: source.name, err }, 'Context source failed — skipping');
    }
  }
}
```

**Update `chunksTotal`** to include context source chunk count in the progress reporting. Since we don't know context source chunk counts upfront, update `chunksTotal` after calling `getChunks()`:
```ts
progress.chunksTotal += sourceChunks.length;
```
