    - Test 3: validateCorpus() checks that all expectedFiles exist in the target project
    - Test 4: validateCorpus() returns a report of missing files and duplicate queries
    - Test 5: BenchmarkQuery interface extended with optional `category` and `intent` fields for documentation
  </behavior>
  <action>
    **Extend corpus.ts:**
    1. Add optional fields to BenchmarkQuerySchema: `category` (enum: "semantic", "keyword", "cross-file", "complex-pattern", "negative", "edge-case") and `intent` (string describing why this query matters)
    2. Create `validateCorpus(queries: BenchmarkQuery[], projectRootPath: string): Promise<ValidationResult>` function that:
       - Checks for duplicate query IDs → returns array of duplicates
       - Checks for empty expectedFiles → returns array of invalid queries
       - For each expectedFile, verifies file exists at projectRootPath + expectedFile → returns array of missing files
       - Returns `{ valid: boolean, issues: {duplicates, emptyFiles, missingFiles} }`
    3. Use `fs.access()` (preferred) or glob to verify file existence
    4. Add unit tests in corpus.test.ts (5-7 tests covering all validation cases)
    
    **Rationale:** Validation prevents corpus corruption (queries pointing to non-existent files, duplicates). The category and intent fields enable us to track coverage distribution and justify why each query is included.
