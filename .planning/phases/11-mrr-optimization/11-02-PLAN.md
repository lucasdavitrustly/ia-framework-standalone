# Plan 11-02: Fix Text Vector — Embed Prose Descriptions

**Phase**: 11 — MRR Quick Wins & Corpus Building
**Plan**: 2 of 4
**Depends on**: 11-01 (corpus exists so we can validate after re-index)
**Estimated duration**: ~20 minutes
**Goal**: Replace raw code in the `textVector` with a natural-language prose description of each chunk. This directly targets the root cause of poor semantic search: NLP embedding models can't match code syntax.

---

## Context

**The problem** (confirmed in `packages/indexer/src/pipeline.ts:184,208-209`):

```typescript
const texts = batch.map((c) => c.content);       // line 184 — raw code
const vectors = await embeddingProvider.embedBatch(texts);
// ...
textVector: vector,    // line 208 — same raw-code embedding
codeVector: vector,    // line 209 — same raw-code embedding (intentional for now)
```

Both vectors embed **raw code**. This wastes the `text` vector — NLP models (nomic-embed-text, text-embedding-ada-002) are trained on prose and cannot semantically match queries like "how does the indexing pipeline work" against raw TypeScript AST dumps.

**The fix**: Generate a prose description from chunk metadata and embed that into `textVector`. Keep `codeVector` as raw code (good for identifier-level keyword matching from the code-side model).

**Expected impact**: +15–30% MRR for semantic queries (sem-01 through sem-05 in the corpus).

// packages/indexer/src/chunk-description.ts
import type { CodeChunk } from '@ia-framework/ast-parser';

/**
 * Generate a natural-language prose description of a code chunk for text embedding.
 *
 * NLP embedding models (nomic-embed-text, text-embedding-ada-002) are trained on prose
 * and cannot semantically match queries against raw code syntax. This function converts
 * structured chunk metadata into a sentence that NLP models can embed meaningfully.
 *
 * The codeVector embeds raw chunk.content (good for identifier matching).
 * The textVector embeds this description (good for semantic concept matching).
 */
export function chunkToDescription(chunk: CodeChunk): string {
  const parts: string[] = [];
  const file = chunk.relativePath;
  const lang = chunk.language;

  switch (chunk.chunkType) {
    case 'function':
      parts.push(`${lang} function ${chunk.name ?? 'anonymous'} in ${file}`);
      break;
    case 'class':
      parts.push(`${lang} class ${chunk.name ?? 'anonymous'} in ${file}`);
      break;
    case 'interface':
      parts.push(`TypeScript interface ${chunk.name ?? 'anonymous'} in ${file}`);
      break;
    case 'type':
      parts.push(`TypeScript type alias ${chunk.name ?? 'anonymous'} in ${file}`);
      break;
    case 'enum':
      parts.push(`${lang} enum ${chunk.name ?? 'anonymous'} in ${file}`);
      break;
    case 'module':
      parts.push(`${lang} module file ${file}`);
      break;
    default:
      parts.push(`${lang} code in ${file}`);
  }

  if (chunk.parentName) {
    parts.push(`inside ${chunk.parentName}`);
  }

  if (chunk.exports.length > 0) {
    parts.push(`exports: ${chunk.exports.slice(0, 5).join(', ')}`);
  }

  if (chunk.imports.length > 0) {
    const importedModules = chunk.imports
      .slice(0, 5)
      .map((i) => i.split('/').pop() ?? i)
      .join(', ');
    parts.push(`imports from: ${importedModules}`);
  }

  return parts.join('. ') + '.';
}
```

// Embed raw code for code vectors (identifier/keyword search)
const codeTexts = batch.map((c) => c.content);
const codeVectors = await embeddingProvider.embedBatch(codeTexts);

for (let j = 0; j < batch.length; j++) {
  const chunk = batch[j]!;
  // ...
  vectorPoints.push({
    id: chunk.id,
    textVector: textVectors[j]!, // prose description embedding
    codeVector: codeVectors[j]!, // raw code embedding
    payload,
  });
}
```

**Important**: This doubles embedding API calls per batch (one for prose, one for code). This is intentional and expected — the embedding provider already batches, so cost is 2x per chunk (acceptable). Document this trade-off in the SUMMARY.
