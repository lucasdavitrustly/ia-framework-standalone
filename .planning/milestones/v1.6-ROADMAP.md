# Roadmap — v1.6: RAG Retrieval Quality Improvements (Benchmark-Driven)

## Motivation

Benchmark run (Claude Opus 4.6, 2026-05-15) showed MCP provides +1.1% quality uplift but regresses on keyword lookups (-3pts). This milestone targets the specific regression gaps and latency issues identified.

**Benchmark report:** `.opencode/benchmark/reports/benchmark-2026-05-15-143022.md`

**Baseline (2026-05-15):**

| Metric       | Without MCP | With MCP    | Delta  |
| ------------ | ----------- | ----------- | ------ |
| Quality      | 17.8/25     | 18.0/25     | +1.1%  |
| Cost         | $3.316      | $2.927      | -11.7% |
| Input Tokens | 33,859 avg  | 30,253 avg  | -10.6% |
| Win Rate     | 3/6         | 2/6 (1 tie) |        |

**Key regressions:** keyword -3pts (22→19), cross-file -1pt, negative -1pt, latency 57s on simple queries.
**Key wins:** arch +4pts (14→18), error +2pts (19→21), complex TIE with 94.8% fewer tokens.

**Success criteria:**

1. MCP keyword lookup score >= 22/25 (no regression vs no-MCP baseline)
2. Architectural query quality gain preserved (>= 18/25)
3. Simple query latency < 12s (down from 57s)
4. `benchmark_preflight` tool callable and passing
5. Hybrid search outperforms pure semantic on cross-file queries (>= 20/25)
6. Overall MCP win rate >= 4/6

## Phase Details

### Phase 37: Query Complexity Classifier

**Goal**: Simple keyword/symbol lookups bypass vector search and go directly to file access tools, eliminating the -3pt regression on keyword queries.
**Depends on**: Nothing
**Success Criteria** (what must be TRUE):

1. A query like "find class OrderController" routes to direct file search, not vector search
2. A query like "how is the payment flow structured?" routes to vector search as before
3. Classification is rule-based (no LLM call), adding <5ms overhead
4. Keyword lookup benchmark scores match or exceed no-MCP baseline
5. Architectural query scores remain at +4pts gain
   **Plans**: TBD

### Phase 38: Line-Number-Aware Chunking

**Goal**: RAG responses can cite exact source locations (file:line) for every retrieved chunk.
**Depends on**: Nothing
**Success Criteria** (what must be TRUE):

1. Every chunk in Qdrant has `startLine` and `endLine` in its payload metadata
2. MCP tool responses include line number ranges in returned context
3. Re-indexing preserves line numbers through the full pipeline (AST parse → chunk → embed → store)
4. Line numbers are validated against source files during indexing (no stale data)
   **Plans**: TBD

### Phase 39: Confidence-Based Early Exit

**Goal**: Skip vector search entirely when the query is simple enough for direct file tools or when retrieval confidence would be low.
**Depends on**: Phase 37
**Success Criteria** (what must be TRUE):

1. Simple symbol lookups complete in <12s (down from 57s)
2. Low-confidence queries return a "no relevant context" signal instead of noisy results
3. Early exit decision is logged for observability
4. No false positives — complex queries still go through full retrieval
   **Plans**: TBD

### Phase 40: Benchmark Preflight Tool

**Goal**: A `benchmark_preflight` MCP tool validates that all required benchmark tools are callable before a run starts.
**Depends on**: Nothing
**Success Criteria** (what must be TRUE):

1. `benchmark_preflight` tool is registered in MCP server
2. Tool checks reachability of all required MCP tools (search, hybrid search, module deps, etc.)
3. Returns structured pass/fail per tool with error details
4. Benchmark CLI calls preflight before starting a run and aborts with clear message on failure
   **Plans**: TBD

### Phase 41: Hybrid Retrieval Tuning

**Goal**: Hybrid search (keyword + semantic) outperforms pure semantic search on cross-file queries.
**Depends on**: Phase 37
**Success Criteria** (what must be TRUE):

1. Cross-file queries score higher with hybrid than pure semantic (measured by benchmark)
2. Keyword/semantic weight ratio is configurable in project config
3. RRF fusion parameters are tunable without code changes
4. A/B benchmark comparison shows measurable improvement on deps-cross-file prompts
   **Plans**: TBD
