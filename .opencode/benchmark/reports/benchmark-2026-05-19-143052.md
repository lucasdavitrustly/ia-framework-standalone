## RAG Improvement Insights

### Identified Weaknesses

- **Completeness (-4.3pt avg regression)**: MCP-enhanced responses consistently lacked end-to-end flow descriptions despite having access to more code
  - **Root Cause Hypothesis**: Retrieved chunks are individual files/functions rather than connected flows. The model gets fragments but can't reconstruct the full pipeline.
  - **Affected Component**: Chunking strategy, dependency graph expansion

- **Reliability (catastrophic failure on Prompt 2)**: Model entered infinite tool-call loop consuming 111K input tokens
  - **Root Cause Hypothesis**: No guardrail on tool-call rounds. Model keeps searching for "better" context instead of synthesizing what it has.
  - **Affected Component**: MCP server tool design, prompt engineering

- **Context Dilution (+60% tokens, -18% quality)**: More context actively hurt response quality
  - **Root Cause Hypothesis**: Low relevance threshold returns marginally related code that confuses rather than clarifies. Signal-to-noise ratio is too low.
  - **Affected Component**: Retrieval scoring, re-ranking, relevance threshold

- **Factual Precision (Prompt 5 judge confusion)**: Judge couldn't distinguish target project technologies from framework technologies
  - **Root Cause Hypothesis**: Benchmark judge prompt doesn't clearly separate target project context from framework context
  - **Affected Component**: Benchmark judge prompt template

### Proposed Improvements (Prioritized)

| #   | Improvement                  | Affected Package    | Effort | Expected Impact                                   |
| --- | ---------------------------- | ------------------- | ------ | ------------------------------------------------- |
| 1   | Tool-call round limiter      | packages/mcp-server | S      | Eliminates timeout failures (+17pt on Prompt 2)   |
| 2   | Stricter relevance threshold | packages/core       | M      | Reduces noise, improves completeness (+2-3pt avg) |
| 3   | Flow-aware chunking          | packages/core       | L      | Improves end-to-end comprehension (+2-4pt)        |
| 4   | Judge context separation     | packages/benchmark  | S      | Eliminates false hallucination penalties (+2-4pt) |
| 5   | Adaptive retrieval depth     | packages/mcp-server | M      | Prevents over-retrieval on simple queries         |

**Details:**

1. **[P1] Tool-call Round Limiter**
   - **Problem**: Prompt 2 consumed 180s and 111K tokens without producing an answer
   - **Proposed Solution**: Add a max-rounds parameter (default: 3) to MCP tool handlers. After N rounds, force synthesis with retrieved context. Alternatively, add a "synthesize now" system prompt after detecting 3+ consecutive tool calls.
   - **Affected Package**: packages/mcp-server
   - **Expected Impact**: Eliminates timeout failures. Prompt 2 score would likely be 20-25/30 instead of 10/30.
   - **Effort Estimate**: Small (configuration + prompt engineering)
   - **GSD Phase Goal**: Implement tool-call round guardrail to prevent runaway retrieval loops

2. **[P2] Stricter Relevance Threshold**
   - **Problem**: MCP adds 60% more tokens but quality drops 18%. Retrieved context has low signal-to-noise.
   - **Proposed Solution**: Raise similarity score threshold from current value to 0.75+. Limit results to top-3 most relevant chunks per query. Add a relevance re-ranker using cross-encoder or LLM-based scoring.
   - **Affected Package**: packages/core (retrieval logic)
   - **Expected Impact**: Fewer but higher-quality chunks. Expected +2-3pt avg quality improvement and -30% token reduction.
   - **Effort Estimate**: Medium
   - **GSD Phase Goal**: Implement relevance re-ranking to maximize signal-to-noise in retrieved context

3. **[P3] Flow-aware Chunking**
   - **Problem**: Without-MCP consistently provides better end-to-end flows. MCP retrieves fragments without connection.
   - **Proposed Solution**: During indexing, build a call-graph/dependency-graph. When a chunk is retrieved, optionally include its upstream/downstream neighbors. Use tree-sitter to identify method call chains.
   - **Affected Package**: packages/core (indexer, chunking)
   - **Expected Impact**: Improves completeness dimension by +2-4pt for cross-file and flow questions.
   - **Effort Estimate**: Large
   - **GSD Phase Goal**: Build flow-aware context expansion that retrieves connected code paths

4. **[P4] Judge Context Separation**
   - **Problem**: Judge confused ia-framework (TypeScript) with target project (Java/Spring Boot), penalizing correct answers as hallucinations
   - **Proposed Solution**: Update judge prompt to explicitly state: "The target project is [X]. References to [target project technologies] are expected and correct."
   - **Affected Package**: packages/benchmark
   - **Expected Impact**: Eliminates false hallucination penalties. Prompt 5 MCP score likely 16-18/30 instead of 12/30.
   - **Effort Estimate**: Small
   - **GSD Phase Goal**: Add target project context to judge evaluation prompt

5. **[P5] Adaptive Retrieval Depth**
   - **Problem**: Simple questions (Prompt 5: "Does it use WebSocket?") don't need deep retrieval but get it anyway
   - **Proposed Solution**: Classify query complexity before retrieval. Simple yes/no questions get shallow retrieval (1 round, 2 chunks). Complex architecture questions get deep retrieval (3 rounds, 8 chunks).
   - **Affected Package**: packages/mcp-server
   - **Expected Impact**: Reduces over-retrieval on simple queries. Faster response + less noise.
   - **Effort Estimate**: Medium
   - **GSD Phase Goal**: Implement query complexity classifier to adapt retrieval depth

MCP should be **disabled in production** until P1 (round limiter) and P2 (relevance threshold) are implemented. After those fixes, re-run the benchmark to validate improvement.

2. **Short-term**: Relevance threshold tuning + result count limiting
3. **Medium-term**: Flow-aware chunking with call-graph expansion
4. **Long-term**: Query complexity classification for adaptive retrieval

1. **Fix P1 immediately** — The timeout failure is unacceptable in production
2. **Fix P4 (judge calibration)** — Re-score Prompt 5 with corrected judge to get accurate baseline
