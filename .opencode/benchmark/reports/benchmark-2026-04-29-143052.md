## RAG Improvement Insights

### Identified Weaknesses

- **Negative Query Handling**: MCP retrieves irrelevant context for "does X exist?" queries, adding 47% token cost with zero quality improvement.
  - **Root Cause Hypothesis**: Retrieval doesn't distinguish "find evidence of X" from "confirm absence of X" — always returns top-K results regardless of relevance threshold.
  - **Affected Component**: Retrieval layer (score threshold / empty-result signaling)

- **Edge-Case Depth**: MCP slightly underperformed on error handling patterns (-1 pt), suggesting retrieved chunks may not include full class hierarchies.
  - **Root Cause Hypothesis**: Chunking strategy splits class inheritance trees across multiple chunks, losing hierarchical context.
  - **Affected Component**: Indexer (chunking strategy for class hierarchies)

- **Semantic Coverage Ceiling**: Even with MCP, architecture queries only scored 23/30 — suggesting retrieval misses some high-level design documentation or README context.
  - **Root Cause Hypothesis**: README/architecture docs may not be indexed, or their embeddings don't rank highly for "architecture" queries.
  - **Affected Component**: Indexer (document type coverage), embedding model (doc-vs-code semantic gap)

### Proposed Improvements (Prioritized)

| #   | Improvement                                        | Affected Package    | Effort | Expected Impact                             |
| --- | -------------------------------------------------- | ------------------- | ------ | ------------------------------------------- |
| 1   | Relevance threshold with empty-result signaling    | packages/core       | S      | Negative queries: -45% cost, 0 quality loss |
| 2   | Hierarchy-aware chunking for class trees           | packages/core       | M      | Edge-case: +1-2 pts                         |
| 3   | Index README/architecture docs with boosted weight | packages/core       | S      | Semantic: +1-2 pts                          |
| 4   | Query intent classification (existence vs search)  | packages/mcp-server | M      | Negative queries: skip retrieval entirely   |
| 5   | Adaptive retrieval depth by query complexity       | packages/mcp-server | L      | All categories: optimize token usage        |

**Details:**

1. **[P1] Relevance Threshold with Empty-Result Signaling**
   - **Problem**: Benchmark shows MCP retrieves context for negative queries (WebSocket check) adding 47% tokens with zero quality gain.
   - **Proposed Solution**: Add a minimum similarity score threshold (e.g., 0.65). When no results pass threshold, return an explicit "no relevant code found" signal instead of low-relevance chunks.
   - **Affected Package**: packages/core (retrieval module)
   - **Expected Impact**: Eliminate wasted tokens on negative queries (-$0.46/negative prompt), maintain quality.
   - **Effort Estimate**: Small
   - **GSD Phase Goal**: Add configurable relevance threshold to vector search with empty-result signaling

2. **[P2] Hierarchy-Aware Chunking for Class Trees**
   - **Problem**: Error handling prompt lost 1 point — MCP missed the full RuntimeException inheritance tree that base context captured.
   - **Proposed Solution**: During indexing, detect class hierarchies via AST and ensure parent-child relationships are preserved in a single chunk or linked via metadata.
   - **Affected Package**: packages/core (indexer/chunker)
   - **Expected Impact**: Edge-case and cross-file prompts: +1 pt average
   - **Effort Estimate**: Medium
   - **GSD Phase Goal**: Implement AST-aware chunking that preserves class inheritance context

3. **[P3] Index Architecture Documentation with Boosted Relevance**
   - **Problem**: Architecture queries scored only 23/30 — high-level design intent not fully captured.
   - **Proposed Solution**: Index README.md, ARCHITECTURE.md, and doc/ files with a relevance boost (1.5x) for "architecture", "design", "overview" queries.
   - **Affected Package**: packages/core (indexer)
   - **Expected Impact**: Semantic/architecture prompts: +2 pts
   - **Effort Estimate**: Small
   - **GSD Phase Goal**: Add documentation file indexing with semantic boost for overview queries

4. **[P4] Query Intent Classification**
   - **Problem**: MCP doesn't distinguish "find X" from "does X exist?" queries.
   - **Proposed Solution**: Simple intent classifier (regex + heuristics) that detects negative/existence queries and either skips retrieval or uses stricter thresholds.
   - **Affected Package**: packages/mcp-server
   - **Expected Impact**: Negative queries: eliminate unnecessary retrieval, save ~30K tokens/query
   - **Effort Estimate**: Medium
   - **GSD Phase Goal**: Add query intent detection to MCP tool dispatch layer

5. **[P5] Adaptive Retrieval Depth**
   - **Problem**: All queries use same retrieval parameters regardless of complexity.
   - **Proposed Solution**: Classify query complexity and adjust top-K, chunk count, and context window allocation accordingly.
   - **Affected Package**: packages/mcp-server
   - **Expected Impact**: Optimize token usage across all categories (-15% avg tokens, maintain quality)
   - **Effort Estimate**: Large
   - **GSD Phase Goal**: Implement adaptive retrieval parameters based on query complexity classification
